# MoreImg 可复用开发经验

这份文档记录能迁移到类似轻量 AI 工作台的判断规则，不记录一次性聊天过程、临时文件名或具体 API Key。

## 1. 静态展示与运行服务要分开

当 GitHub Pages 只承担应用展示时，发布物只应包含页面实际加载的 HTML、JS、CSS、字体、图标和导出依赖。Python 代理、测试夹具、源码、截图和本地维护文档不应被当成线上运行条件。

静态页面直连模型接口的前提是：接口支持浏览器跨域、HTTPS、用户自行配置密钥。若页面配置了 `localhost` 或 `127.0.0.1`，线上必须立即阻止请求并提示改用可跨域 HTTPS 接口，不能让请求进入长时间等待状态。

发布前建立明确的运行文件清单；不要根据 `git status` 看到什么就上传什么。

## 2. 先判断“流式”是否给用户带来价值

流式请求只有在用户能看到实时增量内容，或网关需要持续消费上游响应时才值得承担传输成本。

如果界面在请求期间展示独立加载页，直到完整结果返回才显示内容，那么流式响应通常只有成本没有收益：每个片段都可能触发文本拼接、阶段解析和应用重渲染，而用户仍看不到中间结果。此时优先使用一次非流式 JSON 请求，完整返回后解析一次。

当前核心加工采用 `stream: false`，与连接测试保持同一响应协议，避免部分中转站或思考模型返回非标准流式事件后被误判为空内容。页面收到完整 JSON 后再统一解析和渲染；如未来重新启用流式，也必须同时保留普通 JSON 回退。

选择非流式模式的代价是没有真实阶段进度，因此加载页只能表达“处理中”，不能把进度条当成后端真实完成度。若产品保留阶段文案或模拟进度，应把它视为等待态的视觉叙事，成功、失败、停止和结果状态必须来自真实请求状态。

## 3. 高风险热点：逐片更新整个 SPA

以下组合容易导致拖动、滚动和输入卡顿：

- 每个 SSE 片段都调用 `setState`。
- 每次更新都从头解析不断变长的完整文本。
- 页面把输入、历史、结果、HTML 卡片和生图控件放在同一个大组件。
- 背景使用大面积模糊、持续形变动画或多个 `backdrop-filter`。

优先顺序：先移除无收益的逐片更新；仍需流式时再按时间窗口批量刷新，并只更新可见结果；HTML 合成和图片控件在结果完成或用户进入对应视图后再挂载；背景动画默认保持静态，低性能设备不承担持续大面积合成。

## 4. 异步主流程必须形成闭环

主操作至少要覆盖：点击后立即进入 pending、重复点击被阻止、停止按钮可取消、超时能退出、成功展示结果、失败保留原输入并给出可恢复路径。按钮文本、禁用状态、加载层和错误提示必须由同一份请求状态驱动，不能出现按钮显示处理中但请求已结束，或请求仍在跑但操作入口消失的情况。

对长请求使用 `AbortController`，并设置明确的总超时。停止和超时都要走统一的收尾逻辑，清空请求引用、恢复按钮和解除加载层。

## 5. 诊断顺序

遇到“页面卡住”时，按以下层次取证，不先改视觉：

1. 浏览器 Network：请求是否发出、TTFB、HTTP 状态、响应头和响应体格式。
2. 配置边界：当前页面是否误用了本机代理地址，接口是否允许跨域。
3. 传输模式：接口是否真的返回 SSE；非标准流、网关缓冲和完整 JSON 要分开处理。
4. 主线程热点：是否每个片段都触发全量解析和 React 重渲染。
5. 渲染负担：动画、模糊、图片解码、HTML 卡片和 IndexedDB 是否在当前路径实际执行。

每次只验证一个假设；先写能在旧行为上失败的回归契约，再做最小修复。

## 6. 最小验证梯度

- 请求/状态契约：针对本地代理地址、超时、取消、普通 JSON 和空响应写定向测试。
- 构建契约：确认 `index.html` 和 `app.js` 已由源码重新生成。
- 页面检查：桌面和窄屏至少各一次，确认首屏可见、无横向溢出、控制台无明显错误。
- 发布检查：只暂存已确认的运行文件，检查远程分支同步后再提交推送。

测试全绿只说明覆盖到的运行行为成立，不能替代真实浏览器中的加载、按钮、滚动和主流程检查。
